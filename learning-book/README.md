# 从 Web 开发到 AI 应用工程

## 以 WeKnora 为范本的源码学习书

> 本书面向熟悉 Java、Vue 和传统 Web 开发，但尚未系统参与 AI 应用开发的工程师。
>
> 对应源码版本：WeKnora `main` 分支，首次整理基线为 `0cc3c335`（2026-08-12）。

这不是 WeKnora 的使用手册，也不是把源码换一种说法重新注释一遍。它试图回答另一类问题：

- 一个成熟 AI 应用究竟由哪些部分组成？
- LLM、Embedding、向量数据库和 Rerank 分别解决什么问题？
- RAG 为什么不只是“搜索后调用一次大模型”？
- Agent 和普通后端工作流有什么本质差异？
- 一个可以演示的 AI Demo，怎样演进成可维护、可观测、可评测的工程系统？
- WeKnora 做出了哪些设计选择？这些选择何时适用，又付出了什么代价？

本书把 WeKnora 当作一位“优秀的同行”。我们先学习它如何思考和组织问题，再阅读它的具体实现。

## 两条彼此独立的路线

### 阅读路线：本书

阅读路线的目标是建立完整、可迁移的 AI 应用工程知识体系。即使暂时不运行项目、不写实验代码，也可以连续阅读。

每章包含：

1. 要解决的问题；
2. 通用概念和心智模型；
3. 与传统 Java/Web 开发的对应关系；
4. WeKnora 的具体实现；
5. 推荐阅读的源码入口；
6. 设计取舍与常见误区；
7. 可选实践入口。

### 实践路线：实验与独立项目

实践路线用于验证理解，包括运行 WeKnora、修改参数、观察中间结果，以及用 Java/Vue 实现 Mini RAG。它会单独编写，不作为继续阅读本书的前置条件。

书中出现的“可选实践”可以跳过。跳过后不影响后续章节。

## 推荐阅读顺序

## 当前版本能带你学到什么

当前章节已经形成从 LLM 输入、完整 RAG 到 Agent 工具循环的连续主线：

1. 建立 AI 应用的分层视角；
2. 把 LLM 从“智能黑盒”还原为有明确接口和限制的组件；
3. 理解 Token、上下文预算、消息协议与 Prompt 构造；
4. 建立按质量、延迟、成本、合规和运维选择模型的框架；
5. 理解 RAG 的知识准备与在线问答两条生命周期；
6. 沿 WeKnora 源码看清文档入库与流式问答；
7. 深入 Chunking、Embedding、关键词检索、向量检索和 RRF 融合；
8. 理解 Rerank、MMR、父子 Chunk、相邻扩展、上下文与引用构造；
9. 建立覆盖检索、生成和系统质量的 RAG 评测框架；
10. 理解 Function Calling、Tool Schema 与应用执行权之间的边界；
11. 把 ReAct 还原成带状态、预算、错误与终止条件的工程循环；
12. 理解 MCP 如何统一外部工具发现与调用，以及协议没有替代的安全责任；
13. 理解 Skills 的渐进式披露，以及脚本、沙箱、会话文件和产物之间的执行边界。

读完以后，你应该能独立画出 WeKnora 完整 RAG 主链和 Agent 工具循环，解释内置 Tool、MCP Tool 与 Skill 的层次关系，沿证据链诊断错误回答，并识别模型提议、远程服务与沙箱执行之间的安全边界。

## 版本与勘误原则

WeKnora 会持续演进，文件和行号可能变化。书中链接优先指向稳定的文件和类型/函数名；行号只用于快速定位，不被视作知识本身。

当源码变化时，更新顺序是：

1. 先确认架构含义是否改变；
2. 再更新调用链和源码入口；
3. 最后调整具体行号和代码片段。

这样可以避免把书写成只能对应某次提交的“源码快照”。
