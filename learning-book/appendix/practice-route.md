# 附录 D　实践路线总目录

[返回全书目录](../README.md)

本路线是可选的。每一项都可独立完成，不是阅读后续章节的前置条件。实践前请使用隔离测试数据、独立 API Key，并避免把生产密钥写入日志或提交到仓库。

| 路线 | 目标 | 关联章节 | 完成证据 |
| --- | --- | --- | --- |
| 1. 运行与观察 | 启动一个本地实例并识别前端、App、存储和模型边界 | 1、27 | 能解释一条请求经过哪些进程/服务 |
| 2. RAG 最小闭环 | 上传一份可公开测试文档，问一个可定位答案的问题 | 5–12 | 回答带可回查引用，且能区分检索错与生成错 |
| 3. Chunk 实验 | 比较两种切分设置的召回差异 | 6、8 | 保存 Chunk 预览和三个代表性查询 |
| 4. 检索诊断 | 比较关键词、向量、混合检索与 Rerank | 9–12 | 记录候选、最终上下文、延迟与错误案例 |
| 5. 流式恢复 | 在回答中断开/刷新客户端并观察状态 | 7、22 | 能区分展示恢复与计算恢复 |
| 6. Agent 最小工具 | 设计一个只读工具 Schema，并测试正常、无参、越权输入 | 13–17 | 服务端对模型参数重新校验的测试或日志 |
| 7. 文档与图片 | 用带图片的文档检查 OCR、Caption、图片检索边界 | 18–20 | 写出文本代理检索与原生多模态检索的区别 |
| 8. 异步失败演练 | 让一个可逆测试任务超时/失败，检查最终业务状态 | 21、23 | 状态、重试和人工恢复路径清晰可见 |
| 9. 观测与安全 | 用 Request ID 追一条请求，并验证无权限资源被拒绝 | 25、26 | Trace/日志证据与授权拒绝证据 |
| 10. 架构设计 | 为自己的功能写一页垂直切片蓝图 | 27–31 | 生命周期、预算、权限、状态和升级触发条件 |

## 建议顺序

初学者按 1 → 2 → 3 → 4 → 9 → 10；要做 Agent 再插入 5 → 6；要做企业数据同步或多模态再学习 7 → 8。每次实验只改变一个变量：模型、Chunk、检索开关或超时中的一个，避免把结果归因给错误因素。

## 实验记录模板

```text
目标：
输入与数据范围：
配置变化：
预期：
实际结果：
证据（Request ID / 截图 / Trace / 引用）：
失败分类：检索 / 生成 / 权限 / 队列 / 外部依赖
下一步：
```

好的实践不是“跑通一次”，而是能解释一次失败发生在哪个边界、证据在哪里，以及下一次应改变什么。
