# 附录 B　核心术语表

[返回全书目录](../README.md)

## Adapter

适配器。把某个外部 Provider 或协议的鉴权、请求、响应和错误转换为应用内部稳定接口。多模型系统中 Adapter 应隐藏供应商差异，但不应假装所有 Provider 的能力完全相同。

## Agent

让模型在循环中根据当前状态选择下一步动作的应用架构。动作可能是回答、检索知识、调用 API、执行代码或使用 MCP 工具。Agent 不是某一种模型名称。

## ASR

Automatic Speech Recognition，自动语音识别。把音频中的语音转写为文本；它与读取音频容器、说话人分离和语义摘要是不同处理步骤。

## Asynq

基于 Redis 的 Go 异步任务队列库。WeKnora 标准模式使用它完成任务入队、延迟执行、重试、Queue 调度、Worker 并发与任务检查。

## BM25

经典关键词相关性算法，综合词频、逆文档频率和文档长度评估文本匹配。擅长错误码、名称和精确术语，与向量检索互补。

## Backpressure

背压。消费者处理速度低于生产者时，用缓冲上限、批量、流量窗口、降采样或暂停生产等机制防止内存和延迟无限增长。AI token 流还要考虑前端渲染速度与事件存储容量。

## Caption

对图片主要内容和语义关系的文字描述。它适合主题和场景检索，与恢复精确字符的 OCR 互补；Caption 仍是模型生成文本，可能遗漏细节或产生幻觉。

## Cardinality

基数。一个观测字段可能出现多少种不同值。把 User ID、Session ID 或 UUID 直接用作 Metric Label 会产生极高基数并显著增加存储与查询成本；它们更适合作为 Log/Trace 属性。

## Chat Model

接收角色消息并生成文本或工具调用的模型能力。可以非流式或流式返回。

## CDC

Change Data Capture，变更数据捕获。通过日志、版本号或变更事件持续获取新增、更新和删除。外部 SaaS Connector 与 CDC 相似，但第三方 API 提供的时间戳、分页和删除信号通常比数据库日志更弱。

## Checkpoint

检查点。长任务已经安全完成到某个位置的持久快照，失败重试可从该位置恢复。检查点必须与实际副作用对齐；先保存进度再落库可能永久漏数据。

## Chunk

文档经过解析和切分后形成的知识片段，是检索、引用和上下文构造的基本单位。

## Connector

把外部系统认证、资源枚举、变化检测和内容格式转换适配到应用统一接口的组件。持续同步中的 Connector 不只是 API Client，还必须定义稳定身份、Cursor、删除与部分失败语义。

## Context Window

模型一次请求能够处理的 Token 总量范围，通常包括系统消息、历史、检索证据、工具定义、当前问题和输出。

## Dead Letter Queue

死信队列。任务超过重试预算或遇到不可恢复错误后的保留区，用于调查、告警、人工重放或补偿。进入死信不等于用户可见的业务状态已经自动收口。

## Decorator

装饰器。在不改变核心能力接口的前提下包裹实现，统一增加 Trace、Debug、并发治理、指标或日志等横切能力。

## Dependency Inversion

依赖倒置。高层业务依赖自己需要的稳定能力抽象，外部模型、数据库或协议实现反向实现这些抽象。它不是简单地“多写一个接口”，关键在于接口由应用需求而不是供应商 SDK 形状定义。

## Cursor

增量读取或同步的恢复位置，可以是分页令牌、提交 SHA、更新时间集合或 Connector 自定义状态。可靠 Cursor 应表示此前数据已经产生可接受的持久效果，而不只是“API 已经读到这里”。

## Embedding

将文本、图片等内容映射为浮点向量的过程或模型能力。相近语义通常在向量空间中距离更近。

## Entity Linking

实体链接或实体消歧。把文档中的名称、简称和别名映射到规范实体，同时区分同名不同对象。知识图谱与跨文档 Wiki 去重都依赖这一能力。

## EventBus

在应用内部发布和消费事件的机制。WeKnora 用它传递检索阶段、答案增量、引用、完成和错误等运行事件。

## Function Calling / Tool Calling

模型按照工具 Schema 生成结构化调用意图，由应用执行实际工具，再把结果返回模型。模型本身通常不会直接执行函数。

## Fan-out / Fan-in

扇出与扇入。父任务把工作拆成多个可并行子任务是 fan-out；等待或聚合所有子任务结果、再推进整体状态是 fan-in。可靠实现需要处理部分入队失败、重复完成和并发计数。

## Generation

可观测性中的一次模型调用记录，通常包含模型、输入、输出、参数、Usage、错误、开始和结束时间。它是 Trace 的子节点，不等于产品中的一整轮会话。

## Human-in-the-loop

在自动流程的高风险或不确定节点暂停，等待人类审批、修改或拒绝后再继续。Agent 中常用于外部写入、删除、发送、支付或权限敏感工具。

## IDOR

Insecure Direct Object Reference，不安全的直接对象引用。攻击者通过猜测或替换资源 ID 访问他人对象。多租户系统必须把 ID 解析回 Tenant 与资源归属，而不能只检查 ID 格式或对象是否存在。

## IR

Intermediate Representation，中间表示。不同输入或供应商结果先转换到统一结构，供后续步骤稳定消费。文档管线常使用 Markdown 加图片/元数据作为通用 IR，但复杂版面还可能需要结构化 Block 与坐标。

## Hallucination

模型生成看似合理但缺乏事实依据、与证据冲突或完全错误的内容，通常译作“幻觉”。

## Groundedness / Faithfulness

生成答案中的事实是否得到给定检索证据支持，常译为“有依据性”或“忠实性”。它不同于答案是否碰巧正确：模型可能依靠参数记忆答对，但没有使用或遵守当前证据。

## Hybrid Search

组合向量语义检索、关键词检索或其他召回方式，再对结果进行归一化、融合和去重。

## Knowledge Base

WeKnora 中组织文档、FAQ、模型、切块和检索配置的业务容器。

## Knowledge

WeKnora 中一份导入的文件、URL 或手工文本对应的知识记录。它属于某个 Knowledge Base。

## Knowledge Graph

以节点和类型化边组织实体、概念与关系的知识结构。Graph RAG 通常先用图扩展相关对象，再回到来源 Chunk 取得可验证证据。

## Layout Analysis

版面分析。识别页面中的标题、正文、栏、表格、图片、页眉页脚等区域，以及它们的层级与阅读顺序。它不等同于只把像素识别成字符的 OCR。

## Least Privilege

最小权限。主体只获得完成当前任务所需的最小操作、资源、时间与网络范围。AI Agent 中通常表现为 Tool Allow-list、对象 Scope、短期凭证、审批和 Sandbox 限制的交集。

## LLM

Large Language Model，大语言模型。工程语境中常特指处理消息并生成文本/工具调用的基础模型服务。

## MCP

Model Context Protocol。用于统一 AI 应用与外部工具、资源和提示之间交互的协议。它降低工具接入耦合，但不自动解决权限和可信执行问题。

## Multimodal RAG

能够处理文本、图片、音频等多种模态证据的检索增强生成。实现可以使用 OCR/Caption 文本代理，也可以建立共享的跨模态向量空间；使用 VLM 本身不等于完成了多模态检索。

## Multi-tenancy

多租户。多个逻辑空间共享应用与基础设施，同时在身份、数据、配置、密钥、任务、缓存和观测层保持隔离。仅给业务表增加 `tenant_id` 不能自动形成完整隔离。

## Ontology

本体或领域概念模型。规定允许的实体类型、关系类型和约束，使知识图谱抽取与查询使用稳定语义，而不是让模型自由创造节点和边类别。

## Idempotency

幂等性。同一个操作重复执行一次或多次，最终效果与执行一次相同。网络失败后的自动重试若作用于非幂等写工具，可能制造重复工单、重复发送或重复扣款。

## Observation

Agent 执行动作后获得的可观察结果，可以是工具数据、业务失败或执行错误。Observation 会进入下一轮上下文，供模型决定继续、换方法或结束。

## Outbox

事务发件箱。先把业务状态与“待发送操作”写入同一数据库事务，再由独立派发器可靠投递到消息队列。它缩小数据库提交成功而消息发送失败造成的不一致窗口；消费者仍需幂等。

## OCR

Optical Character Recognition，光学字符识别。把图片或扫描页面中的文字像素转换为字符。OCR 字符正确并不保证阅读顺序、表格结构和标题层级正确。

## MAP

Mean Average Precision，平均准确率均值。它综合一个查询中多个相关结果出现的位置，再对所有查询取平均，适合评估需要召回多份相关证据的检索任务。

## MMR

Maximal Marginal Relevance，最大边际相关性。选择候选时同时奖励查询相关性、惩罚与已选结果的相似性，用于减少 Top-K 中的重复内容。

## MRR

Mean Reciprocal Rank，平均倒数排名。用第一个相关结果排名的倒数衡量检索效果，越早出现相关结果分数越高。

## nDCG

Normalized Discounted Cumulative Gain，归一化折损累积增益。综合相关性等级和排名位置，靠后的相关结果贡献更小。

## Prompt

发送给模型的指令和内容。成熟系统中通常由模板、历史、检索证据、用户输入、工具定义等共同构成，更广义的概念是上下文工程。

## Prompt Injection

提示注入。用户或外部文档通过指令性文本诱导模型忽略原规则、泄露信息或调用不当工具。真正的防线必须位于模型外部，包括权限校验、Tool Scope、审批、Sandbox 与出站策略。

## Provider

提供模型能力的供应商或运行平台，例如 OpenAI、Anthropic、Azure OpenAI 或本地 Ollama。Provider 名称、配置元数据与实际协议 Adapter 是相关但不同的层次。

## RAG

Retrieval-Augmented Generation，检索增强生成。在生成前动态检索外部知识，并将证据放入模型上下文。

## Precision

准确率。在检索评测中表示返回结果里有多少真正相关，常写为 Precision@K。它与 Recall 形成取舍：结果更少、更严格时 Precision 可能提高，但可能漏掉相关证据。

## Principal

当前请求最终代表的调用主体。它可能是真人账号、API Key、外部用户、IM 用户或嵌入访客；Principal 用于主体级状态隔离，不应自动继承某个 User 的全部 RBAC 权限。

## Progressive Disclosure

渐进式披露。先向模型提供轻量元数据，在任务匹配后再加载完整说明和附属资源，以减少无关上下文和能力选择噪声。Skills 常采用这种模式。

## RBAC

Role-Based Access Control，基于角色的访问控制。权限由主体在某个范围内的角色决定；多租户系统通常还要叠加资源归属、共享关系和对象 Scope。

## Recall

召回。检索系统从大规模数据中找出候选的过程；评测中的召回率描述应该找到的相关内容有多少被找到了。

## ReAct

一种常见 Agent 模式，通过推理、行动和观察结果的循环逐步完成任务。工程实现必须增加终止条件、权限、超时和错误处理。

## Rerank

对第一阶段召回的候选进行更精细的相关性重排。通常输入查询和候选文本，输出新的分数或顺序。

## Replay

回放。新消费者或重连客户端从事件存储重新读取已经产生的事件，以重建当前 UI 或处理状态。事件回放只能恢复已记录输出，不等于恢复已经崩溃的模型或工具计算。

## RRF

Reciprocal Rank Fusion，倒数排名融合。根据候选在多条结果列表中的排名计算融合分，不要求向量分和关键词分处于同一尺度。

## Sandbox

限制代码进程、文件、网络、CPU、内存、时间和凭证访问的隔离执行环境。不同实现的隔离强度不同；名称中含有 Sandbox 不代表它天然适合执行不可信代码。

## Skill

面向一类专业任务的模块化能力包，通常包含名称、描述、操作说明、参考文件、模板和可选脚本。Skill 描述方法，可以编排多个 Tool；它本身不能扩大应用授予的权限。

## Span

Trace 中一个有开始、结束和父子关系的工作单元，例如检索阶段、Agent Round、Tool Call 或 Worker Handler。业务数据库中的处理 Span 可能与 OpenTelemetry Span 同名但承担不同生命周期。

## SSRF

Server-Side Request Forgery，服务端请求伪造。攻击者诱导服务端访问内网、云元数据或其他受保护地址。租户可配置的 MCP 和沙箱远程端点需要保存时与实际拨号时的双层防护。

## BLEU / ROUGE

通过词或子序列重合比较生成文本与参考文本的自动指标。适合低成本回归，但不能单独证明事实正确、忠于证据或引用有效。

## SSE

Server-Sent Events。服务器通过一个 HTTP 连接持续向浏览器发送事件。WeKnora 用它承载答案增量、进度、引用和完成状态。

## Tombstone

删除墓碑。表示某个稳定身份对象已在源端删除的显式事件或记录。完整变更日志中的 Tombstone 通常比“本轮列表没有看到该对象”更可靠，后者可能只是部分失败或权限变化。

## Trace

一次请求或任务的端到端调用树，由 Root 与多个 Span/Generation 组成。分布式系统通常通过 W3C `traceparent` 在 HTTP、消息队列和 Worker 之间传播上下文。

## Temperature

影响模型采样分布的参数。通常更高会增加多样性，也可能降低稳定性；具体范围和行为依供应商而异。

## Token

模型处理文本时使用的离散单位，不严格等于字或单词。输入、输出、上下文限制和计费通常都以 Token 计算。

## Tool Call

模型生成的一次结构化工具调用意图，通常包含调用 ID、工具名称和 JSON 参数。它不是已执行操作；应用仍需解析、校验、授权并调用真实工具。

## Tool Schema

描述工具名称、用途和参数结构的模型接口契约，通常使用 JSON Schema。它帮助模型选择工具和生成参数，但不能替代对象级权限、业务规则与执行安全检查。

## Top-K

只保留排序最靠前的 K 个结果。RAG 中可能分别存在召回 Top-N、Rerank Top-K 和最终上下文 Top-K，含义不要混淆。

## TTFT

Time To First Token，从模型调用开始到收到第一个有效输出 Token 的时间。它主要反映排队、网络与 Prompt Prefill，不等于完整生成耗时或用户端到端延迟。

## Vector Database / Vector Store

支持存储向量并执行近邻搜索的数据库或检索后端。它可能是专用向量数据库，也可能是带向量扩展的 PostgreSQL、SQLite 或搜索引擎。

## VLM

Vision-Language Model，视觉语言模型。能够联合处理图片与文本，用于图片理解、OCR 后校正、说明生成或多模态问答。

## Worker Pool

消费一组 Queue 的并发执行资源。Pool 的并发数决定同时执行多少任务，Queue 权重决定可选任务之间的调度偏好；两者都不等于模型供应商的 RPM、TPM 或连接配额。
