# 本书写作与源码引用规范

[返回全书目录](README.md)

这份规范保证后续章节保持“学习书”而不是产品手册或源码注释的形态。

## 读者假设

- 熟悉 Java、Vue、HTTP、数据库和常见 Web 分层；
- 不假设读者具有机器学习训练经验；
- 不假设读者熟悉 Go；
- 新术语第一次出现时必须用普通工程语言解释。

## 单章固定结构

完整章节原则上包含：

1. 本章要解决的问题；
2. 通用原理；
3. 与传统 Web/Java 的对应；
4. WeKnora 的选择；
5. 关键流程图或数据结构；
6. 源码观察点和推荐阅读顺序；
7. 设计取舍与失败模式；
8. 本章小结；
9. 可选实践。

可以按主题删减，但不能只罗列文件。

## 通用原理与项目选择必须分开

应使用类似表达：

- “RAG 通常需要控制最终上下文预算。”
- “WeKnora 当前通过 `FILTER_TOP_K` 阶段完成最终过滤。”

不能把当前实现写成唯一正确答案，也不能只讲通用概念而不落到项目。

## 源码引用规则

1. 优先链接到文件，并在正文写出稳定符号名。
2. 只有关键入口才附行号。
3. 不复制大段源码；代码片段只用于突出接口或主干。
4. 链接使用相对路径，使书稿随仓库一起移动仍可访问。
5. 行号变化时，以函数、类型和事件名称为准。
6. 每章主源码入口控制在 3～8 个，更多入口放入源码地图。

## 图示规则

- 图用于解释阶段、数据流、状态或依赖；
- 单一事实不画图；
- 首次出现复杂管线时画全景，后续章节只画局部；
- 节点名称使用业务含义，文件名放正文而不是塞入图中。

## 实践与正文分离

- 实践统一放在章末，明确标记“可选实践”；
- 不使用“完成练习后才能继续”之类前置要求；
- 大型实验、Java Mini RAG 和环境搭建放入独立实践路线；
- 正文必须在不运行代码的情况下仍然完整可读。

## 版本纪律

章节更新时记录所依据的提交。若源码发生变化：

1. 检查概念和架构是否改变；
2. 检查调用链；
3. 检查符号名；
4. 最后校准行号和链接。

## 完成标准

一章达到“可读”状态至少应满足：

- 能独立解释一个完整问题；
- 包含 WeKnora 真实实现依据；
- 源码链接存在；
- 清楚区分原理与项目选择；
- 至少指出一个设计代价或失败模式；
- 不依赖可选实践才能理解后续章节。
