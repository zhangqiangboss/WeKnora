# 导读：如何阅读本书与 WeKnora 源码

[返回全书目录](README.md)

## 这本书不是按仓库目录写的

大型项目最容易让初学者掉进一个陷阱：从入口文件开始，沿每一次函数调用一路追下去。很快你会同时遇到鉴权、租户、数据库、日志、异常、兼容逻辑和业务分支，最后记住了许多类名，却没有形成 AI 系统的心智模型。

本书采用相反的顺序：

1. 先定义当前要理解的问题；
2. 建立不依赖 WeKnora 的通用模型；
3. 再看 WeKnora 如何解决它；
4. 最后进入几个能代表设计意图的源码位置。

因此，章节顺序与仓库目录不会一一对应。同一个章节可能同时引用前端、Handler、Service、模型适配器和存储实现。

## 三种阅读深度

### 第一层：只读正文

目标是理解概念、组件关系和设计取舍。可以完全不打开源码。

适合第一次通读。遇到暂时陌生的术语，先查看[核心术语表](appendix/glossary.md)，不要立即扩散阅读十几个外部主题。

### 第二层：正文加源码入口

每章会列出少量“主源码入口”。打开文件后，先寻找书中指出的函数、接口或事件类型，只阅读它的输入、输出和主干分支。

第一遍建议主动略过：

- RBAC 与 API Key 的完整判断矩阵；
- 跨租户共享知识库；
- 多供应商的特殊兼容分支；
- 大量错误包装和日志字段；
- 与本章主题无关的异步清理逻辑。

这些不是不重要，而是不应同时进入工作记忆。

### 第三层：验证调用链

在理解章节后，使用 IDE 的“查找引用”“转到实现”“调用层次结构”验证书中的主链路。

此时建议做一张自己的小图，只记录：

```text
输入 → 核心状态 → 关键阶段 → 输出
```

不要抄录整个函数调用树。调用树描述代码怎样走，心智模型解释系统为什么这样走。

## 怎样阅读 Go，而不先学完 Go

你已有 Java 经验，可以先使用下面的近似映射：

| Go/WeKnora | Java 中可类比的概念 |
|---|---|
| `struct` | 主要承载字段的数据类，或带方法的普通类 |
| `interface` | Java interface，但由实现方隐式满足 |
| `func (s *X) Method` | 类 `X` 的实例方法 |
| `context.Context` | 请求上下文、取消信号、超时和链路元数据的组合 |
| goroutine | 轻量并发任务，不等同于直接创建 OS 线程 |
| channel | 带同步语义的类型化消息通道 |
| `error` 返回值 | 显式错误通道，而不是以异常为默认控制流 |
| Gin Handler | Spring MVC Controller 方法 |
| Service / Repository | 与常见 Java 分层基本同义 |
| 构造函数与工厂 | 常承担 Spring Bean 创建和策略选择的职责 |

这个映射不是语言规范，但足以支撑第一遍源码阅读。遇到 goroutine、channel、defer 或 interface 断言影响业务语义时，再针对性补 Go 语法。

## 每章中的四种内容标记

本书使用以下语义区分内容：

- **通用原理**：离开 WeKnora 仍然成立。
- **WeKnora 的选择**：项目针对自身目标做出的具体设计。
- **源码观察点**：打开源码时要回答的问题。
- **可选实践**：用于验证理解，可以跳过。

如果某个实现只是当前版本细节，会明确写成“当前实现”，避免把项目选择误写成行业定律。

## 为什么先读 RAG，再读 Agent

Agent 看起来更接近今天的 AI 热点，但它把许多问题叠加到了一起：

- 模型消息和上下文；
- 工具描述与参数 Schema；
- 多轮状态机；
- RAG 检索；
- MCP；
- 权限和沙箱；
- 超时、重试与循环终止；
- 流式事件展示。

如果先理解 RAG，就已经掌握了模型调用、上下文构造、检索质量和流式输出。再学习 Agent 时，只需增加“模型决定下一步动作”的循环，而不是一次面对全部复杂度。

WeKnora 的普通知识问答和 Agent 问答也有明确入口区分：

- 普通知识问答入口：[`KnowledgeQA`](../internal/handler/session/qa.go#L791)
- Agent 问答入口：[`AgentQA`](../internal/handler/session/qa.go#L817)

这使它天然适合按这个顺序学习。

## 一次有效的源码阅读应留下什么

读完一章后，不要求记住所有函数名。你应该能留下四样东西：

1. 一句话解释本章组件解决的问题；
2. 一张不超过十个节点的流程图；
3. 三到五个稳定源码入口；
4. 至少一个你能说清楚的设计取舍。

例如，读完 RAG 问答链路后，你应能解释：为什么先召回较多候选，再 Rerank 并过滤，而不是把所有命中片段直接交给 LLM。

## 关于实践

本书与实践路线不会强绑定。你可以采用任意一种节奏：

- 先通读第一、二篇，再统一实践；
- 每读一章做一次小实验；
- 只读书，把实践留到工作中出现真实需求时；
- 先运行项目建立感性认识，再回到本书整理知识。

实践不是“证明你认真学习”的作业。它的价值是暴露那些仅靠阅读不容易察觉的边界条件。
